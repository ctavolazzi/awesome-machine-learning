# Resource Explorer MVP Walkthrough

This guide demonstrates the minimum viable product that now ships inside
`examples/resource_explorer`. It shows how the markdown-backed loader,
terminal explorer, chart generator, and dashboard exporter work together
so you can validate the MVP end to end in a few commands.

## 1. Load and Inspect the Curated Data

```bash
python -m examples.resource_explorer.app browse --list-categories
```

The command prints a Unicode table listing every category and the source
markdown file that populates it. Pick a category (for example,
`frameworks`) and run:

```bash
python -m examples.resource_explorer.app browse --category frameworks --list-sections
```

You will see the normalized section titles along with counts so you can
spot coverage gaps before diving deeper.

## 2. Search Across Sections

```bash
python -m examples.resource_explorer.app browse --category books --search "deep learning" --limit 5
```

Search results are rendered as numbered rows with aligned section titles
and descriptions, making it easy to skim the curated content without
scrolling through raw markdown.

## 3. Generate the Coverage Chart

```bash
python -m examples.resource_explorer.app chart --category frameworks --output docs/dashboard_chart.svg
```

The CLI reuses the normalized dataset to produce a deterministic SVG bar
chart. Inspect `docs/dashboard_chart.svg` in a browser or vector viewer
and you will see section counts rendered with a dedicated label column,
alternating row backgrounds, dashed tick guides, wrapped breadcrumb-style
names, auto-sized rows that prevent overlapping lines, and right-aligned
totals. Regenerate the asset with `--limit` to focus on the busiest
sections.

## 4. Export the HTML Dashboard

```bash
python -m examples.resource_explorer.app dashboard --category frameworks --output docs/dashboard.html
```

Opening `docs/dashboard.html` in your browser reveals the final MVP
experience:

- A hero metrics strip at the top summarizing total resources, populated
  sections, and the number of cards that match the current filters.
- The same coverage chart from step three embedded inline so the page is
  self-contained. Labels now live in a numbered sidebar with alternating
  backgrounds while the bars inherit the dashed tick grid, making dense
  sections easier to scan than earlier prototypes.
- Responsive resource cards grouped by section, each showing titles,
  descriptions, and tags pulled from the markdown source.

For a ready-to-share example, check in
`docs/resource_explorer_dashboard_sample.html`, which is regenerated by
the command above whenever the data or templates change.

## 5. Validate with Automated Tests

```bash
pytest examples/resource_explorer/tests
```

The suite confirms that markdown ingestion, normalization, dashboard
rendering, and CLI dispatch continue to behave as expected. Keeping this
command in your local workflow ensures the MVP stays healthy as the
curated lists evolve.

## 6. Where to Go Next

- Update the curated markdown files and rerun the commands to refresh the
  dashboard artifacts.
- Extend the tests with additional fixtures when you add new categories
  or adjust the HTML layout.
- Wire the commands into CI to regenerate the sample dashboard on every
  pull request if you need always-fresh documentation.

With these steps, you have seen the MVP in action and can confidently
share the dashboard output with stakeholders.
